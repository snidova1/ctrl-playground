# Cozy life physical integration implementation plan

Goal: Finish a playable staging release: opt-in world-space garden, place/remove crafted decorations, eat and share actual meals. No financial rewards or revenue implementation. Preserve dirty tree, existing home/avatar and furniture features.
Architecture: Extend existing JSON LifeState additively and normalize legacy records. Parent integrates a read-only R3F world layer; panel invokes validated actions. Keep life-owned decorations separate from free builder objects to prevent duplication/refund. Shared meals use real server escrow/claim state (no NPC/tamurekaan).
Stack: Existing React/Three/TypeScript/Zod/D1/Vitest/Playwright.

## Stable extension contract
Domain exports:
- LifeState optional `gardenAnchor?: {x:number;z:number}` (absent -> NO physical garden), `decorations?: Array<{id:string;itemId:'flower-pot'|'wooden-bench';x:number;z:number;rotation:number}>`, `mealsEaten?:number`.
- LifeAction additions: `{type:'place-garden',x,z}`, `{type:'place-craft',itemId,x,z,rotation}`, `{type:'remove-craft',id}`, `{type:'eat',itemId:'garden-soup'|'grilled-fish'}`. Planting doesn't force physical props; user explicitly places garden. Local placement bounds x -13..13,z -7..11 and max 20 decorations; no seeds/crops injected.
- LifeResponse optional `servings?: Array<{id:string;makerId:string;makerName:string;itemId:'garden-soup'|'grilled-fish';createdAt:number;mine:boolean}>`. POST additional commands `{type:'serve',itemId}`, `{type:'eat-serving',servingId}` handled by server. One actual meal removed on serve; exactly one authenticated claimant eats it atomically. Guest local serve is explicitly a local picnic, never fake shared server state.
- `GET /api/cozy-life/world?worldId=UUID` returns sanitized `{beds,gardenAnchor?,decorations}` for world.owner_id, only after Habitat private/public/member ACL. No inventory, wallet, trades or private identity data. Profile required as existing identity. Avoid creating homes or claiming Keys.
- On local or server activity mutation/refresh client dispatches `cozy-life-state` CustomEvent detail `{state:LifeState,local:boolean,community?:LifeResponse['community']}` to synchronize scene, not mutate inventory through an event.
- World click/E entry protocol remains `cozy-life-open` detail `{tab:'garden'|'craft'|'kitchen'...}`. Native dialog captures controls.
